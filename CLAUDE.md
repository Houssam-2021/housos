## What HoussamOS is

A gaming-ready Linux desktop for everyday users, made by Houssam (GitHub `Houssam-2021`).
Built on **Bazzite** (Fedora Atomic / bootc, KDE Plasma 6) with the Universal Blue image template.

- Repo: https://github.com/Houssam-2021/housos (public; repo name stays `housos`, the OS is "HoussamOS")
- Images (public on GHCR, built daily and on every push):
  - `ghcr.io/houssam-2021/houssamos` from `ghcr.io/ublue-os/bazzite:stable` (AMD/Intel, VMs)
  - `ghcr.io/houssam-2021/houssamos-nvidia` from `ghcr.io/ublue-os/bazzite-nvidia:stable`
    (NVIDIA closed driver, supports GeForce 900/10 series such as Houssam's GTX 1080 Ti; Bazzite
    pairs it with its LTS kernel 6.18)
- History: started as an AI-written hobby kernel in the parent folder (`housos_kernel`,
  ~2,500 lines, mostly unwired stubs). Houssam switched to a Linux distro; the kernel is unused.
- Goal: own identity (design + features no other distro combines), not just a rebrand.

## How it is built

| Path | Role |
|---|---|
| `Containerfile` | `ARG BASE_IMAGE` (Bazzite variant), `ARG IMAGE_NAME`; runs `build_files/build.sh` |
| `build_files/build.sh` | copies `system_files/` to `/`, os-release/branding, design packages, KDE defaults, repo cleanup, **rebuilds the initramfs last** and fails if the boot animation is missing from it |
| `system_files/` | files copied into the image as-is (mostly generated by `branding/`) |
| `branding/make_wallpapers.py` | procedural "Aurora" wallpapers, dark + light, 3840x2160 -> `branding/src/wallpaper-*.jpg` |
| `branding/make_theme.py` | Plasma theme `houssamos-glass` (vector SVG frames + blur masks, dock indicators `widgets/tasks.svg`) and colour schemes `HoussamOSDark` / `HoussamOS`; **one PALETTE drives all colours** |
| `branding/make_cursor.py` | cursor theme `HoussamOS-Cursor` from Houssam's arrow `src/cursor.png` (Xcursor, 24-96 px, soft shadow); other cursors inherit Bibata-Modern-Classic |
| `branding/make_branding.py` | boot animation frames (Plymouth) from `src/boot-animation-purple.mp4` (background colour read from the video; also writes the login splash logo `splash/images/boot-logo.png`), H/HOS icons from the white `src/boot-animation.mp4`, wordmark, wallpaper package, installer art, Global Theme previews, startup sound. Run it after the two above; then `git checkout` `startup.oga` if nothing changed (ffmpeg output differs every run) |
| `branding/houssamos.script.in` | Plymouth script template (frames loaded lazily, re-centred every refresh) |
| `branding/make_icons.py` | generates the v2 Studio 3D `HoussamOS-LiquidGlass` icon theme (`Inherits=Tela-dark,breeze-dark,breeze,hicolor`) as SVGs into `system_files/usr/share/icons/HoussamOS-LiquidGlass/scalable`; `build.sh` renders them to PNGs with librsvg (see Lessons) |
| `branding/LiquidGlassClock.qml` | lock screen clock: date over liquid glass digits (Inter Display semibold `Text` masks + `MultiEffect`): the wallpaper (found through LockScreenUi's `WallpaperFader`) shows through blurred, magnified and more vivid, with gloss, bright top-left rim and soft shadow; plain digits without a GPU. Blurred, masked `MultiEffect`s need `autoPaddingEnabled: false` or the mask lands bigger and shifted |
| `branding/import_icons.py` | legacy importer for the earlier Grok "Liquid Glass" icon zip |
| `branding/src/` | Houssam's own art: `boot-animation.mp4`, `logo-wordmark.png`; plus generated wallpapers and the icon zip |
| `.github/workflows/build.yml` | matrix of the two images; cosign signing is skipped until a `SIGNING_SECRET` repo secret exists |
| `.github/workflows/build-disk.yml` | ISOs with bootc-image-builder (run directly, not the deprecated action). Triggers: after a push-triggered image build, on pushes to `disk_config/**` or itself, or manually. Swaps HoussamOS pictures into the ISO's `install.img` (falls back to the unbranded ISO with a warning). Failures are copied into public annotations |
| `disk_config/iso.toml` | kickstart `bootc switch` to the image (the workflow substitutes each image); Localization module for language/keyboard screens |
| `disk_config/installer/` | installer pictures (from `make_branding.py`, incl. the bokeh backdrop `houssamos-bg.jpg`) and `houssamos.css` (purple backdrop, frosted glass panel), which build-disk.yml appends to Anaconda's `anaconda-gtk.css` and to the profile's `custom_stylesheet` (Fedora's `fedora.css`, loaded after it). Anaconda is GTK 3: its CSS nodes are `AnacondaHubWindow`, `AnacondaSpokeWindow`, `AnacondaStandaloneWindow` (each holds a `box.background` with `#nav-box` on top), `.logo-sidebar`/`.logo`; the main window is `window > overlay > stack` |

KDE pieces in `system_files/`:
- Global Themes `usr/share/plasma/look-and-feel/org.houssamos.glass.desktop` (dark, the default; defaults +
  splash `Splash.qml`) and `org.houssamos.glasslight.desktop` (light: HoussamOS colours, light glass Plasma
  theme, `HoussamOS-LiquidGlass-Light` icons = links to the same PNGs with `Tela` behind them; build.sh
  copies the splash and lock screen into it). kdeglobals `DefaultDarkLookAndFeel`/`DefaultLightLookAndFeel`
  make the dark mode switch (Brightness & Color, System Settings) flip between the two
- Plasma themes `usr/share/plasma/desktoptheme/houssamos-glass` and `houssamos-glass-light` (generated)
- Layout scripts `usr/share/plasma/shells/org.kde.plasma.desktop/contents/updates/houssamos-layout*.js`:
  top bar (H menu, clock, tray) + floating centred dock that fits its apps. **Plasma runs each script
  once per user, per filename**: new behaviour for existing desktops needs a new file name
  (`houssamos-layout-2.js` resizes panels; `-4` removes Bazzite Portal; `-5` makes the dock dodge windows
  so it always floats, and pins files, browser, Steam, Konsole, System Settings; build.sh deletes
  Bazzite's `bazzite-pins.js`; `-3` looked for the wrong name and does nothing).
- `usr/libexec/houssamos-user-setup` + `etc/xdg/autostart/houssamos-user-setup.desktop`: applies the
  look once to accounts that existed before (their saved KDE settings override `/etc/xdg`). Raise
  `LOOK_VERSION` (now 5) to re-apply after a design change.
- Terminal: `usr/share/ublue-os/motd/template.md` (ASCII logo banner), `usr/share/houssamos/fastfetch.jsonc`
  + aliases in `etc/profile.d` and fish `vendor_conf.d`, Konsole profile/colour scheme `HoussamOS`.
- Icons: H (small) / HOS (large) in hicolor; build.sh replaces Bazzite/Fedora `distributor-logo`,
  `bazzite-logo`, `start-here` icons everywhere with the H.
- Window animations: KWin effect `usr/share/kwin/effects/houssamos_appzoom` (JavaScript): windows grow
  out of their dock icon (or the middle of the dock when KWin doesn't know the icon yet) and shrink back
  into it on close/minimize, `OutQuart` (closest to iOS's curve), 520 ms open / 375 ms close. While it
  moves the window is frosted glass (see-through with KWin's blur behind it via
  `WindowForceBlurRole`; content fades in as it lands). build.sh turns it on and KDE's
  scale/glide/fade/squash/magic lamp off.
- Login screen: Bazzite's desktop image uses KDE's Plasma Login Manager, whose screen is compiled into
  its program (can't be restyled). build.sh installs SDDM + `sddm-wayland-plasma` + `sddm-breeze` (Fedora
  44 has it only in updates-testing), removes Plasma Login Manager and enables SDDM (as Bazzite's deck
  image does), then copies the Breeze login theme to `/usr/share/sddm/themes/houssamos`, swaps in
  `LiquidGlassClock.qml` like the lock screen, sets the HoussamOS logo and makes it the default
  (`/etc/sddm.conf.d/zz-houssamos.conf`). If SDDM can't be installed, Plasma Login Manager stays. A
  broken theme makes SDDM fall back to its built-in one.
- Bazzite's look removed in build.sh: `bazzite-portal`, Bazzite/uBlue wallpapers, its docs shortcut,
  announcements, dock pins. Its gaming parts (Steam/game mode setup, drivers, hardware fixes, updates) stay.
- Control Center widget `usr/share/plasma/plasmoids/org.houssamos.controlcenter` (QML, macOS style): button
  at the right of the top bar (`houssamos-layout-6.js`); Wi-Fi, Bluetooth, airplane mode, Do Not Disturb,
  screenshot, settings, brightness and volume sliders, now playing. Each system connection is its own
  file in `contents/ui/backends/` loaded by a `Loader` (KDE's private plugins: plasma-nm, bluezqt,
  plasma-pa, powerdevil brightness, mpris, notificationmanager, plasma5support), so one that fails to
  load only hides its part. Preview the layout on Windows with PySide6 and mock backends.
- Cursor theme `usr/share/icons/HoussamOS-Cursor` (generated); build.sh links `left_ptr`, `arrow`,
  `top_left_arrow` to `default`.
- `etc/xdg/plasma-workspace/env/houssamos-caches.sh`: at login, clears KDE's icon/theme/QML caches when
  `/usr/share/houssamos/build-id` (written by build.sh) changed.

## Lessons learned (avoid repeating these)

- **Plasma stops a floating panel from floating whenever a window touches it**, unless its visibility
  is not "always visible" (Panel.qml); hence the dock dodges windows.
- **Translucent shading split across a frame's nine pieces shows seams** where Plasma joins them (seen
  on the dock and the old indicator tile); keep translucent frames one flat colour.
- **KWin script shaders**: `effect.addFragmentShader(Effect.MapTexture, "x.frag")` loads
  `contents/shaders/x_core.frag` on GLSL 1.40+/ES 3 (write `#version 140`; KWin rewrites it for ES) and
  `x.frag` on older GL; use `sampler`, `texcoord0`, `modulation`, `fragColor`. Animate uniforms with
  `type: Effect.ShaderUniform, uniform: "name", fragmentShader: id`. **A blur shader applied this way to
  the windows behind drew them black in the VM (2026-10-21); removed. Don't retry without a way to test.**
- **KWin 6.5's blur applies only contrast and saturation from plasmarc** (`BlurEffect::colorMatrix`);
  `intensity` is ignored, and contrast below 1 washes the blurred background grey (our old 0.25 made the
  dock look like flat grey transparency). Brightness has to come from the theme's own fill. Preview glass
  honestly: keep the wallpaper sharp around it, and behind it blur (PIL GaussianBlur ~28 px for
  BlurStrength 12), apply saturation then contrast, then the theme's fill.
- **The SDDM theme step broke the image build twice** (b250037, ef382a9; exit 1 in Build Image, logs
  need a GitHub login), because the base image had no SDDM at all (Plasma Login Manager). It now finds
  the Breeze login theme by its `Main.qml` and only warns if it can't make the HoussamOS theme. Whether the theme was made shows in the build log ("Login screen: ...") or
  on screen; `ls /usr/share/sddm/themes` in the VM tells which themes exist.
- **Plasma frame pieces must be whole pixels**: a stroke in a corner piece pokes half a pixel out, so
  `boundsOnElement` gives 18.5 and Plasma lays the frame out in fractions (seams). Draw outlines as
  filled shapes. For translucent fills use `hint-compose-over-border` (needs `mask-center`): the centre
  is stretched over the whole frame and cut by the mask, so the fill has no joins.
- **KDE draws icons and Plasma theme SVGs with Qt SVG, which can't draw SVG filters** (blur, drop shadow,
  lighting): they come out as grey boxes and hard blobs. Never use filters in `make_theme.py`; the
  Liquid Glass icons use them, so `build.sh` renders every icon to PNG with librsvg (16-256 px, plus @2x)
  and ships only the PNGs. To preview what KDE will draw, render with PySide6 (`QSvgRenderer`, QML).
- **Image-based systems give every file the same timestamp**, so KDE's icon, theme and QML caches never
  notice an update; `houssamos-caches.sh` clears them when the build changes. The Plasma theme `Version`
  in `make_theme.py` also changes its cache file name.
- **KDE's lock screen draws a drop-shadowed copy of the clock** (`clockShadow`, passed as `shadow`); a
  see-through clock must hide it or it looks solid. The date needs
  `Qt.formatDate(date, Qt.locale(), Locale.LongFormat)`; with `Locale.LongFormat` alone it means
  `Qt.TextDate` ("Wed Oct 21 2026").
- **Bazzite Portal is `io.github.ublue_os.yafti_gtk.desktop`** (yafti); Bazzite's dock pins are browser,
  Steam, Lutris, Konsole, Bazaar (its app store), yafti, file manager.
- **During the container build, `/ctx` contains only `build_files` and `system_files`** (`Containerfile`
  `ctx` stage); anything else (such as `branding/LiquidGlassClock.qml`) must be explicitly `COPY`-ed into
  the `ctx` stage in `Containerfile`.
- **Terra's `tela-icon-theme` only installs `Tela`, `Tela-light` and `Tela-dark`** (`install.sh` with no
  colour argument installs only the "standard" variant). `Tela-blue-dark` does not exist and causes
  missing/blank icons (`System Settings`, `Konsole`). Always use `Tela-dark`.
- **KDE Plasma 6 lock screen layout**: `kscreenlocker_greet` loads `Plasma/Shell`
  (`/usr/share/plasma/shells/org.kde.plasma.desktop/contents/lockscreen/LockScreenUi.qml`), and
  `LockScreenUi.qml` imports `org.kde.breeze.components` (which is precompiled into
  `libcomponentsplugin.so`). `build.sh` copies `lockscreen` and `components` into
  `org.houssamos.glass.desktop/contents/`, installs `LiquidGlassClock.qml` and `Clock.qml` in both the
  Global Theme and `org.kde.plasma.desktop`, and rewrites `Clock {` to `LiquidGlassClock {` in
  `LockScreenUi.qml` (plus clamps `y > 0` for small windows) so the compiled QRC module cannot shadow
  our clock.

- **The Bash tool eats backslashes** in heredocs and inline Python (`\\` becomes `\`, `\n` can become
  a real newline). For text with backslashes use the Write/Edit tools, or `chr(92)` in Python.
- **ISO build fixes** (all in place): Bazzite disables `terra-mesa` through dnf5 overrides that
  bootc-image-builder ignores -> build.sh copies overrides into `.repo` files and disables repos with
  missing GPG keys. "mount /dev permission denied" -> podman storage reset, AppArmor userns sysctl,
  `ubuntu-24.04` runner.
- build.sh prints its failing command as a `::error` annotation (ERR trap), readable without a login.
  A build can fail once for no reason of ours (5afca30 failed in Build Image after 5 min; the same code
  passed on the next push), so look at the annotation before changing anything.
- GitHub job logs need a login. Read failures from check-run annotations
  (`api.github.com/repos/Houssam-2021/housos/check-runs/<job id>/annotations`) or the public run
  page in the browser. The unauthenticated API allows 60 requests/hour.
- ISO artifacts need a GitHub login to download, so Houssam downloads them himself.
- Pushing anything except README/disk config starts a new image build and **cancels a running one**
  (concurrency). Batch changes; don't push while a build you need is running.
- On Windows git, set executable bits with `git update-index --chmod=+x <file>`.
- **Plasma's dark mode switch applies whole Global Themes** (`DefaultDarkLookAndFeel` /
  `DefaultLightLookAndFeel` in kdeglobals `[KDE]`, KDE defaults Breeze Dark / Breeze). Unset, it threw
  Houssam's desktop back to plain Breeze Dark (2026-10-22); HoussamOS sets both to its own two themes.
- **Look inside the published image without a VM**: get a token from
  `https://ghcr.io/token?scope=repository:houssam-2021/houssamos:pull`, read the manifest and config
  (`history[].created_by` names the packages in each rechunked layer), download single layers (~10 MB/s).
  Files not owned by a package sit in the layer "initramfs ... and rpmostree-unpackaged-content"; tar
  entries are hard links into `sysroot/ostree/repo/objects`, so extract the object (`tar -xOzf`).
  `/usr/share/houssamos/build-id` tells which build it is.
- Bazzite facts: its KDE terminal is Konsole (`kde-ptyxis` wraps it); its desktop image uses Plasma Login
  Manager since Fedora 44 (we switch to SDDM, see KDE pieces); Plasma 6.7, Fedora 44, kernel 7.2; it sets
  `DEFAULT_HOSTNAME="bazzite"` (we override; installed VMs need `hostnamectl set-hostname houssamos`);
  `bazzite-portal` autostarts from `/etc/skel/.config/autostart`; dock pins come from Bazzite's
  `bazzite-pins.js`.
- VMware changes the screen size during boot, so anything drawn at boot must re-centre.
- `sudo bootc upgrade` + restart updates an installed system; `sudo bootc status` shows what it follows.
